## 4b. Slice C step 1 — deterministic 1-D break-even discovery (written; engine NOT run)

Files created: `src/ecobackfire/contracts/discovery.py`, `src/ecobackfire/discovery/{__init__,scoring,engine,loader}.py`, `examples/discovery/d1_rebound_breakeven_scan.toml`, `tests/software/test_discovery_scoring.py`, `tests/software/test_discovery_spec.py`, `tests/scientific/test_discovery_breakeven.py`.
Files modified: none besides this file. `find_breakevens`, `make_g`, `get_metric`, `prepare_inputs`, the model, verification, CLI and `api.py` are reused unchanged.

Design decisions
- `DiscoverySpec` (TOML): model_ref, options, bindings (reuses `Binding`, so provenance/units/uncertainty are the Phase 2 ones), decision metric, `[[parameters]]`, scoring weights. Each parameter has a mandatory `basis`. Explicit ranges may be `user_supplied | estimated | illustrative`; `measured/sourced` ranges are refused until evidence is wired in (Slice D). If low/high are omitted the binding's own interval is used; if there is none the engine raises `ConfigError` rather than invent a range.
- Engine: other inputs held at base; `find_breakevens` scan + Brent; every root becomes a `Candidate` (label `candidate`, bracket, side, residual, trace, hypothesis text, warnings incl. applicability extrapolation). Every parameter ends up in `candidates` or `rejected` with a code: `parameter_not_used_under_options`, `no_sign_change_always_beneficial/never_beneficial/indeterminate`, `discontinuity_suspected`, `root_not_converged`, `evaluation_failed` (e.g. range hits a physical bound).
- Score (explainable, weights stored in the result): proximity (threshold near the base point), magnitude (s/(1+s), swing of the metric over the range / emissions scale), evidence (mean policy weight by provenance class; all-illustrative = 0). Not yet applied and listed as such in every result: robustness under uncertainty, independent verification/falsification, evidence-store resolution. The score ranks attention; it is not a truth measure.

## 4d. Slice D step 1a — falsification checks for 1-D break-even candidates (numerics executed; NOT yet wired to the engine)

Files created: `src/ecobackfire/discovery/falsification.py`, `tests/software/test_falsification_checks.py`.
Files modified: this file only. No existing module, contract, check, example or expected output was changed. Imports only numpy/scipy, `errors`, `core.hashing` and the existing `find_breakevens`/`Root` (layer rules respected; AST test re-run).

What it is
- Pure-numerics, like `regions.py`/`sampling.py`: takes a decision function `g(x)`, a `Root` from the existing `find_breakevens`, and the search range. Every check can FAIL; a failed check stays in the report. Status vocabulary reuses `contracts.verification.CheckStatus` (`passed | failed | limits_claim | inconclusive | skipped`); each check also carries a `category` (`false_crossing`, `numerical_instability`, `boundary_dependence`, `not_reproduced`, `perturbation_fragile`, `not_independently_reproduced`, `false_no_crossing`) so the later classification step can map failures to classes.
- Checks (full mathematical definitions are in the module docstring and copied into every report as `metric_definitions`):
  X1 crossing validity (sign change at several probe distances, direction, continuity ratio); X2 numerical stability (grid refinement, independent 200-step bisection, 1e-10-relative noise shift of the root); X3 boundary dependence (range-normalized edge margin; root persistence and new roots outside the range when the range is expanded); X4 reproducibility (repeat the search, bit-identical roots); X5 controlled one-at-a-time perturbations (preserved fraction per level, finite-difference log-sensitivity S_p = d ln x*/d ln p, dominant input); X6 agreement with caller-supplied independent roots (an empty list = the independent path finds no root = fail); X7 attack on a 'no break-even' verdict (dense re-scan, near-zero interior minimum).
- `FalsificationConfig` holds every threshold (probe fractions, continuity ratio, agreement and noise tolerances, edge margin, expansion, repeats, perturbation levels, dense factor). **These are documented policy choices, not derived from data**; they are recorded in the report and change `report.sha256()` when changed. No seeds are used (everything is deterministic); the perturbation design is deterministic OAT, not random.
- Insufficient information never becomes a pass: no probe fits, no sign-changing bracket, all perturbations invalid, zero-valued base input, unknown beneficial side -> `inconclusive`; no perturbation targets or no independent roots supplied -> `skipped`.
- Reports contain no inf/NaN (mapped to `None`), so they hash canonically.

## 4k. Automated Backfire Hunt (checkpoint 11) — EXECUTED; full suite run

This checkpoint reconciled the contracts, then completed planner, runner, summary, CLI/report, example mission and tests.

**What it does.** `[backfire]` in a mission (or `DiscoverySpec.backfire`) turns on a budgeted, deterministic hunt for where the benefit of the decision function `g` (`g<0` beneficial) disappears or reverses. No new equation: `g` is the existing `make_g` over the model's existing metric (`dC` for rebound).
- Search (`discovery/backfire_search.py`, pure numerics): coarse grid scan with the existing `find_breakevens` -> sub-grid refinement of suspect cells (narrow reversal regions, tangent touches) -> sign intervals per parameter (beneficial / adverse; several separated reversal regions are kept). Non-monotone safe. Every evaluation counted; cap is exact; exhaustion returns `status = budget_exhausted` with unsearched parameters recorded as `budget_exhausted` rejections.
- Parameter selection (`mission/planner.py::backfire_parameters`): mission `[[search]]` parameters + (with `auto_parameters`) every other REQUIRED input that has a documented binding interval. No interval => excluded with reason (bounds are never invented). Evidence constraint of each parameter is disclosed, not clipped. Hunt budget must fit the mission budget.
- Baseline (`BackfireBaseline`): base-input metric, `g`, regime (beneficial / near_break_even / adverse), relative change, chain "Baseline -> Intervention -> metric change -> search region -> candidates".
- Candidates: the EXISTING `Candidate` contract with an optional `backfire` block (metric before/after, estimated break-even + uncertainty, distance from baseline absolute/relative/range-normalized, model ref, assumptions, search configuration). Ranking is the existing transparent score plus a documented well-definedness weight; nothing is tuned toward a backfire.
- Pipeline: search -> candidate -> falsification -> robustness -> evidence challenge -> classification. With a hunt, ALL candidates (up to `budget.max_candidates`) are evaluated, not only `top_k`. Eliminated candidates stay in the result with reasons (`BackfireMissionSummary.outcomes`).

**Remaining core gaps (honest):**
- Search is 1-D per parameter (others at base). Reversal regions that exist only through parameter interactions are not found; no 2-D hunt (the older 2-D region machinery is not coupled to the hunt).
- Documented limits of the numerics: reversals narrower than the local re-scan, between range edge and first grid point, or hidden by plateaus are not detected; absence of a finding is not proof of absence.
- A dip is only detected if a grid point reveals a local extremum; very coarse grids can miss it.
- Evidence sensitivity is only as good as the registry: single-source or range-less inputs yield `evidence_insufficient` (the canonical case today).
- Auto-selected parameters use the binding's own interval (illustrative in the canonical mission), which is a declared range, not an evidence-derived one.
- Robustness perturbations remain one-at-a-time.
- Lint/type errors present (not triaged).
